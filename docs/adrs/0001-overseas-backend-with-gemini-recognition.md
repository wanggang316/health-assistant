# Overseas backend with Gemini for meal recognition

Status: Accepted

The app targets mainly users outside mainland China. Google sign-in and the main vision models are not available from mainland China, and a mainland backend needs ICP filing, app filing, and possibly generative AI filing. Thus the backend runs on an overseas nanops VM, and Gemini (`gemini-3.8-flash`, paid tier) is the meal recognition provider. The backend calls Gemini through Vertex AI (express mode API key, endpoint `aiplatform.googleapis.com`), not through the Gemini Developer API (`generativelanguage.googleapis.com`), because the project key is a Vertex AI key and Vertex AI does not use request data for training. On the DiningBench study (mostly Chinese dishes), Gemini 3 models had the lowest calorie error (about 20% MAPE) at a low cost per photo. Claude is not a production dependency, because Anthropic does not permit use by entities that persons or entities in mainland China or Hong Kong control. See [the model research](../research/2026-11-21-food-recognition-models.md).

Trade-offs: users in mainland China get a slow or no service. The paid tier is necessary because the free tier lets Google use the data. The price of `gemini-3.8-flash` doubles on 2027-01-01. Reconsider if the main users move to mainland China, if the cost or error of Gemini becomes worse than an alternative on our own weighed test set, or if one provider becomes a reliability risk (then add a second provider behind the same backend interface).
